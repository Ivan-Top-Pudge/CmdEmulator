# CmdEmulator

Эмулятор командной строки UNIX-подобной операционной системы с графическим
интерфейсом на Go и Fyne. Вариант №2 практической работы по конфигурационному
управлению.

## Текущий этап

Этап 4: полноценные команды `ls`, `cd`, `du`, `wc` работают с VFS в памяти.
Сохранены GUI, конфигурация и стартовые скрипты этапов 1–3.
Имя окна берётся из XML; при ошибке загрузки рабочее окно не открывается.

## Требования

- Go 1.25 или новее;
- системные зависимости Fyne для используемой операционной системы
  (на macOS — инструменты командной строки Xcode);
- Make.

## Запуск и сборка

```bash
make run ARGS="--config configs/default.json"
```

Прямой запуск:

```bash
go run ./src/cmd/emulator --vfs testdata/stage2-vfs.xml
```

Сборка и запуск исполняемого файла:

```bash
make build
./build/cmd-emulator --config configs/default.json
```

Окно содержит историю команд, приглашение `$ ` и поле ввода. Команда
выполняется по Enter или кнопке «Выполнить». Поле очищается и сохраняет фокус,
история прокручивается к последнему результату. Пустой ввод игнорируется.

## Настройки запуска

| Параметр CLI | Поле JSON | Назначение | По умолчанию |
| --- | --- | --- | --- |
| `--vfs <путь>` | `vfs` | Физический файл VFS | Обязателен в CLI или JSON |
| `--prompt <текст>` | `prompt` | Приглашение REPL | `$ ` |
| `--script <путь>` | `script` | Стартовый скрипт | Отсутствует |
| `--config <путь>` | — | Конфигурационный JSON-файл | Отсутствует |
| `--help`, `-h` | — | Справка без запуска GUI | — |

Поддерживаются формы `--имя значение` и `--имя=значение`. Неизвестные,
повторные и позиционные аргументы считаются ошибкой. Значение после флага
обязательно; для значения, начинающегося с `--`, используйте форму с `=`.

Пример `configs/default.json`:

```json
{
  "vfs": "../testdata/stage2-vfs.xml",
  "prompt": "student@stage2:$ ",
  "script": "../scripts/startup.txt"
}
```

Каждое поле — строка. Неизвестные поля, `null`, неверные типы и лишние данные
после JSON-объекта запрещены. Отсутствующие поля получают значения по умолчанию.

Для каждого поля приоритет: **CLI → JSON → значение по умолчанию**. Например:

```bash
./build/cmd-emulator --config configs/default.json --prompt "override> "
```

Пути из JSON отсчитываются от каталога конфигурационного файла. Пути из CLI
отсчитываются от текущего каталога запуска. Абсолютные пути используются напрямую.
Пример отключения скрипта из JSON: `--script ""`; пустое `--prompt ""` убирает
приглашение. Пустые `--vfs` и `--config` недопустимы.

До создания окна приложение проверяет итоговые пути, загружает XML-VFS в память
и читает скрипт целиком.
Недоступный файл, каталог вместо файла или неверная конфигурация приводят
к сообщению в stderr и коду завершения 1. Неверные XML, права или base64 также
прерывают запуск. Справка и нормальный выход дают код 0.
Перед запуском GUI в stdout выводятся все итоговые параметры с экранированием
строк: `config`, `vfs`, `prompt`, `script`. Отдельно выводится имя загруженной VFS.

## XML-VFS

Минимальный формат:

```xml
<vfs name="demo-vfs">
  <directory name="/">
    <directory name="docs">
      <file name="hello.txt" mode="644">SGVsbG8K</file>
    </directory>
  </directory>
</vfs>
```

`vfs` содержит непустое имя и ровно один корневой каталог `/`. Каталоги
`directory` могут содержать другие каталоги и файлы `file`. Вложенные имена
должны быть непустыми, без `/`, `.` и `..`; имена у одного родителя уникальны.

Атрибут `mode` задаёт три восьмеричные цифры прав: по умолчанию `755` для
каталогов и `644` для файлов. Содержимое каждого файла — base64, включая
текстовые файлы. В примере `SGVsbG8K` означает байты `Hello` и перевод строки.
Пробелы и переносы внутри base64 игнорируются; пустой `file` означает пустой файл.
Неизвестные элементы и текст вне файлов считаются ошибкой формата.

В памяти хранятся имя, тип узла, права, байты файла и дочерние узлы каталога.
Размер файла вычисляется по декодированным байтам. Загрузчик только читает XML:
содержимое не распаковывается на диск, исходный XML не изменяется.

Примеры находятся в `testdata/vfs`: `minimal.xml` — пустой корень,
`multiple.xml` — несколько текстовых и двоичных файлов, `deep.xml` — вложенные
каталоги `/docs/reports/2026` с файлом `summary.txt`.

## Стартовый скрипт

Скрипт — UTF-8-текст с одной командой на строку. Пустые строки и строки,
начинающиеся с `#` после пробелов, пропускаются. Встроенные комментарии после
команды не обрабатываются: `#` внутри команды остаётся обычным символом.
Поддерживаются переводы строк LF и CRLF. Длина строки должна быть менее 1 МиБ.

```text
# Пример скрипта
ls /
ls "$HOME"
cd "my folder"
unknown
ls
```

Скрипт выполняется при запуске цикла Fyne после создания окна. Команды и ответы
попадают в ту же историю и используют то же приглашение, что и ручной ввод.
До завершения скрипта поле и кнопка ввода отключены. Ошибка команды отображается
с номером строки и не останавливает следующие команды.

После скрипта поле ввода включается и получает фокус. Корректный `exit`
закрывает окно и пропускает оставшиеся строки; `exit extra` выводит ошибку
и позволяет скрипту продолжиться. Скрипт `scripts/startup.txt` показывает
штатные команды, раскрытие переменных и ошибки, затем оставляет окно открытым.

## Команды REPL

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `ls [-lha] [путь]` | Флаги вместе или отдельно, один путь, по умолчанию `.` | Список имён |
| `cd [путь]` | Один путь, по умолчанию `/` | Меняет текущий каталог, без вывода |
| `du [путь]` | Один путь, по умолчанию `.` | Сумма байтов файлов для каждого каталога |
| `wc путь` | Один обязательный файл | Число LF, слов и байтов, затем путь |
| `exit` | Без аргументов | Закрывает окно и завершает сеанс |

У `ls` три флага: `-l` добавляет тип, права и размер в байтах; `-h` при `-l`
показывает размеры в B, KiB, MiB и следующих единицах по 1024; `-a` добавляет
скрытые имена, `.` и `..`. Допускаются `ls -lha`, `ls -l -h -a` и `ls путь -lh`.
Имена сортируются лексикографически; `ls файл` выводит сам файл. Размер каталога
в `ls -l` равен нулю; для суммы содержимого используется `du`.
После `--` имена с дефисом считаются путями: `ls -- -dash`.

Абсолютные пути начинаются с `/`, относительные — с текущего каталога сеанса.
`.` пропускается, `..` поднимает на уровень выше в любой части пути:
`cd /docs/reports/../reports/2026`. Выше корня перейти нельзя; повторные `/`
допустимы. Каждый компонент проверяется последовательно: `missing/../docs`
и `file/..` дают ошибку. Неудачный `cd` сохраняет текущий каталог.
`cd` без аргументов возвращает в корень.

`du` рекурсивно считает декодированные байты всех файлов, включая скрытые,
и выводит каталоги после их потомков. Блоки реального диска не учитываются.
`wc` считает переводы строк LF, слова по пробельным символам Unicode и байты;
последняя строка без LF не увеличивает первый счётчик. Каталог для `wc` — ошибка.
Опции у `cd`, `du`, `wc` не поддерживаются; для имён с дефисом используйте `./имя`.
Права хранятся как метаданные: модель пользователей и проверка доступа не реализованы.

Парсер поддерживает одинарные и двойные кавычки, экранирование обратным слешем,
`$NAME` и `${NAME}` из окружения реальной ОС. В одинарных кавычках переменные
остаются текстом. Подставленное значение сохраняется одним аргументом;
неопределённая переменная даёт пустую строку. Ошибки разбора не завершают сеанс.
Конвейеры, перенаправления, подстановка команд и шаблоны файлов не выполняются.

Пример диалога с `testdata/vfs/commands.xml`:

```text
$ cd /docs/../other
$ ls
marker.txt
$ ls -lh /big.bin
-rw-r--r-- 2KiB big.bin
$ wc /text.txt
1 3 10 /text.txt
$ exit extra
Ошибка: shell.Execute: shell.dispatch: exit: команда не принимает аргументы
```

Пути после подстановки окружения всегда относятся к VFS.
Например, `ls "$HOME"` сообщает ошибку, если такого каталога нет внутри VFS.

## Проверки

```bash
make fmt       # форматирование исходного кода
make check     # проверка форматирования и go vet
make test      # тесты shell и GUI без открытия окна
sh tests/stage1.sh  # все проверки и сборка этапа 1
sh tests/stage2.sh  # все проверки, сборка, справка и ошибки запуска этапа 2
sh tests/stage3.sh  # проверки этапов 1–3 и ошибки загрузки VFS
sh tests/stage4.sh  # все проверки этапов 1–4
```

Тесты shell проверяют разбор ввода, переменные, аргументы, ошибки и продолжение
работы после ошибки. Тесты GUI используют драйвер Fyne без настоящего окна:
проверяют Enter, кнопку, историю, фокус, сообщения об ошибках и закрытие окна.
Тесты конфигурации проверяют JSON, приоритет источников и файлы. Тесты скриптов
и GUI проверяют комментарии, номера строк, остановку по `exit` и переход
от стартового скрипта к интерактивному режиму.
Тесты VFS проверяют загрузку примеров, данные и права, неверный формат,
неизменность исходного XML и отсутствие распаковки файлов на диск.

Для демонстрации после `make build` используйте:

```bash
sh scripts/run-cli.sh       # только CLI
sh scripts/run-json.sh      # JSON со стартовым скриптом
sh scripts/run-override.sh  # CLI меняет JSON и отключает скрипт
sh scripts/run-script.sh    # скрипт через CLI
```

Каждый скрипт открывает окно; завершайте сеанс командой `exit` перед следующим
запуском. Полный сценарий с ожидаемыми результатами находится в `tests/stage2.md`.

Демонстрация трёх вариантов VFS после `make build`:

```bash
sh scripts/run-vfs-minimal.sh
sh scripts/run-vfs-multiple.sh
sh scripts/run-vfs-deep.sh
```

Каждый запуск загружает свою VFS и выполняет `scripts/stage3-startup.txt`,
затем оставляет окно для ручного ввода. Ожидаемые результаты — в `tests/stage3.md`.

Демонстрация основных команд: `sh scripts/run-stage4.sh` после `make build`.
Сценарий и ожидаемые ответы описаны в `tests/stage4.md`.
Тесты команд проверяют все сочетания флагов `ls`, сложные пути, ошибки переходов,
точные суммы `du`, Unicode и подсчёт LF/слов/байтов в `wc`.
Сценарии этапов 1–3 в документации описывают исторические версии своих веток.

## Структура

- `src/cmd/emulator` — точка входа приложения;
- `src/internal/shell` — независимая от GUI логика и её тесты;
- `src/internal/gui` — интерфейс Fyne и его тесты;
- `src/internal/config` — разбор CLI, JSON, приоритеты и проверка файлов;
- `src/internal/startup` — чтение и выполнение стартовых скриптов;
- `src/internal/vfs` — XML-формат, загрузка дерева и данных файлов в память;
- `configs` — пример конфигурации;
- `scripts` — скрипты ОС для демонстрации и стартовый скрипт;
- `testdata` — примеры XML-VFS;
- `tests` — проверочный скрипт и сценарий демонстрации;
- `Makefile` — запуск, сборка, проверки и очистка.

Локальные артефакты сборки находятся в игнорируемом каталоге `build`.
Для их удаления используется `make clean`.

Все функции документируются комментариями с описанием поведения и возвращаемых
значений. Ошибки содержат `const op` с именем операции, причины сохраняются через `%w`.
