# Демонстрация этапа 3

Выполните `sh tests/stage3.sh`: проверяются форматирование, `go vet`, все тесты,
сборка, ошибки параметров и отказ от запуска GUI при неверной VFS.

Затем запустите каждый сценарий отдельно, закрывая окно командой `exit`:

| Запуск | Имя VFS в заголовке и терминале | Содержимое в памяти |
| --- | --- | --- |
| `sh scripts/run-vfs-minimal.sh` | `minimal-vfs` | Пустой корневой каталог |
| `sh scripts/run-vfs-multiple.sh` | `multiple-vfs` | Текстовые файлы и двоичный `data.bin` |
| `sh scripts/run-vfs-deep.sh` | `deep-vfs` | Дерево `/docs/reports/2026/summary.txt` |

Все три запуска выполняют `scripts/stage3-startup.txt`: команды с путями VFS,
переменные окружения, неизвестную команду и неверные аргументы. После ошибок
скрипт продолжает работу, затем становится доступен ручной ввод.

На этапе 3 `ls` и `cd` ещё выводят разобранные аргументы. Реальная навигация
и чтение дерева относятся к этапу 4. Данные дерева, base64 и вложенность
проверяются тестами пакета `vfs`.

Для запуска с автоматическим завершением:

```bash
./build/cmd-emulator --vfs testdata/vfs/deep.xml --script tests/data/stage2-exit.txt
```

После сеанса исходный XML должен совпадать с исходной версией; его неизменность
и отсутствие распаковки также проверяются тестами.
