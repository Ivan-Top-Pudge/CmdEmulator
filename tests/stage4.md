# Демонстрация этапа 4

Запуск: `make build`, затем `sh scripts/run-stage4.sh`.
Все команды стартового скрипта и ошибки видны в истории окна.

1. `ls` выводит отсортированные имена без `.hidden`; `ls -a` добавляет
   `.`, `..` и `.hidden`. `ls -lha` объединяет все три флага.
2. `ls -l` показывает тип, права и размер; `big.bin` занимает 2048 байтов,
   при `ls -lh` — `2KiB`. `-h` без `-l` не меняет список имён.
3. `cd .` сохраняет текущий каталог. После `cd reports/2026/../..`
   из `/docs` команда `ls` показывает `reports`.
4. `cd /docs/../other` переходит в `/other`; `ls` показывает `marker.txt`.
   Повторные переходы выше корня оставляют текущий каталог `/`.
   Вызов `cd` без аргументов из `/other` возвращает в корень; последующий
   `ls docs` показывает `reports`.
5. `wc summary.txt` показывает `1 1 8 summary.txt`.
   Для `text.txt` результат `1 3 10 text.txt`; для пустого файла — три нуля.
   Абсолютный путь проверяется через `wc /text.txt`: `1 3 10 /text.txt`.
6. `du /docs` показывает 8 байтов для каждого из трёх вложенных каталогов.
   `du` без аргументов проверяет текущий каталог `/docs/reports/2026`.
   Для файла `du text.txt` выводит `10` и путь через табуляцию;
   для пустого файла `du empty.txt` — `0` и путь.
7. В конце намеренно выполняются шесть ошибочных команд. Ошибки содержат
   причину и номер строки, после них `ls /other` показывает `marker.txt`.
8. Ввести вручную `cd /other`, затем `cd /missing/../docs`, затем `ls`.
   Ошибочный переход сохраняет `/other`, в выводе остаётся `marker.txt`.
9. `exit extra` сообщает ошибку; `exit` закрывает окно.

Автоматическая проверка: `sh tests/stage4.sh`. Тестовый драйвер Fyne проверяет
Enter, кнопку, историю, фокус и исполнение команд после скрипта без открытия окна.
Сценарий этапа 4 также исполняется через тот же обработчик startup.Run в тестах.
Сценарии stage1.md–stage3.md описывают исторические версии соответствующих веток;
в текущей версии `ls` и `cd` уже работают с деревом вместо вывода аргументов.
